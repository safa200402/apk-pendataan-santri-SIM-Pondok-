===================================================================
Ditulis: 2026-07-28
Terkait: frontend/shared-shell.js, backend/server.js


RINGKASAN
---------
Ada 2 sistem popup mengambang yang MIRIP tapi TIDAK SAMA, keduanya hidup
di frontend/shared-shell.js dan dipanggil otomatis tiap halaman dimuat
lewat mount() (baris ~1164-1166):

    syncMaintenanceBanner(options);   // banner maintenance, bukan popup
    syncAnnouncementPopup(options);   // -> sistem PENGUMUMAN
    syncAbsensiHalaqohAudit(options);  // -> sistem AUDIT ABSENSI

Koreksi nama: fungsi audit-nya bernama syncAbsensiHalaqohAudit, BUKAN
"syncAuditAbsensi" (nama itu gampang salah ingat/salah ketik saat mau
grep -- pastikan grep pakai nama yang benar).

Kedua sistem sengaja dipisah biar tidak numpuk di layar:
- Popup pengumuman muncul di kanan-bawah (atau fullscreen kalau
  isFullscreen true).
- Popup audit absensi muncul di kiri-bawah.


1) SISTEM PENGUMUMAN -- syncAnnouncementPopup
----------------------------------------------
Lokasi: frontend/shared-shell.js baris 1205-1404

Alur:
- syncAnnouncementPopup(options) fetch action 'pengumuman.owed' -> dapat
  json.data.items (daftar pengumuman yang belum "dilihat" akun ini).
- Item isFullscreen didahulukan masuk _announcementQueue (antrean
  module-level), baru sisanya.
- showNextAnnouncement(token) nge-render SATU popup dari depan antrean
  (id="_announcementPopup"). Kalau popup itu sudah ada di DOM, fungsi
  langsung return (jaga cuma 1 popup nongol barengan).
- Tema warna per item: ANNOUNCEMENT_THEMES (biasa/merah/jingga/hijau),
  dipilih dari item.colorType.
- Ada 2 varian tampilan: fullscreen (isFullscreen=true, cuma bisa
  ditutup lewat tombol "x", supaya tidak ketutup gak sengaja pas
  scroll baca) dan kartu kecil kanan-bawah (klik di mana saja buat
  tutup).
- Lampiran gambar/video: item.media[]. Klik gambar -> lightbox
  (openAnnouncementImageLightbox), bukan bagian dari popup utama.
- Video wajib-tonton (media.mustWatchFull=true): TIDAK PAKAI native
  'controls' (tidak ada scrubber yg bisa di-skip) -- cuma 4 tombol
  custom: "Open"/"Close" (toggle 1 tombol, label berubah sesuai
  status -- BUKAN Fullscreen API browser, cuma CSS wrap jadi
  position:fixed;inset:0 100% lebar x 100% tinggi layar, murni
  styling supaya konsisten di semua WebView/PWA & tidak switch ke
  player native iOS), "Putar"/"Jeda", dan "-5 detik" (satu2nya cara
  mundur yg diizinkan; anti-skip MAJU tetap berlaku lewat listener
  'seeking' + lastGoodTime). Popup baru bisa ditutup setelah event
  'ended' native tercapai (lihat unfinishedRequiredVideoCount &
  closeAndAdvance). [UPDATE 2026-08-07: sebelumnya Putar/Jeda digembok
  sampai fullscreen (Fullscreen API asli) dimasuki dulu, dengan tombol
  Fullscreen/Keluar Fullscreen/Ulang terpisah -- didesain ulang jadi 1
  tombol toggle Open/Close.]
  [UPDATE 2026-08-07 lanjutan] Putar/Jeda/-5 detik SEMBUNYI (hidden)
  & videonya TIDAK main sama sekali sebelum user klik "Open" --
  enterVideoFullscreen() SEKALIGUS memunculkan ketiga tombol itu DAN

  dalam click handler = ada user gesture). Klik "Close"

  video.pause() -- jadi Putar/Jeda/-5 detik cuma pernah kelihatan &
  bisa dipakai selama wrap-nya dalam status "Open".
- [UPDATE 2026-08-07] Gerbang unfinishedRequiredVideoCount SEKARANG
  juga berlaku di tombol "Kirim Respon" (sebelumnya cuma di tombol "x"/
  closeAndAdvance) -- kalau masih ada video wajib yg belum 'ended',
  submit respon ditolak di frontend (belum sempat fetch ke server sama
  sekali). KEDUA titik ini (closeAndAdvance & handler Kirim Respon)
  SEKARANG menampilkan popup peringatan custom (showAnnouncementVideoWarning_,
  z-index 10020 -- di atas SEMUA overlay lain termasuk pseudo-fullscreen
  video 10010) selain scroll+focus ke videonya, BUKAN cuma diam2 gagal
  spt sebelumnya.
- Ada fitur "Respon" (tombol toggle panel + 2 quick-button "Sudah
  Paham"/"Ada Pertanyaan" + textarea wajib diisi) -> kirim ke action

- "Sudah dilihat" itu STATE YANG DISIMPAN DI SERVER per akun per

2) SISTEM AUDIT ABSENSI -- syncAbsensiHalaqohAudit
----------------------------------------------------

Beda mendasar dari sistem pengumuman: TIDAK ADA state "sudah dilihat"
yang disimpan. Popup ini murni derived dari data live -- begitu
pengampu/pengajar bersangkutan sudah mengisi absensi hari yang bolong,
popup otomatis berhenti muncul sendiri di reload berikutnya (tidak
perlu di-"markSeen").

Alur:
- syncAbsensiHalaqohAudit(options) fetch action 'absensi.owed' ->
  dapat json.data.items, tiap item punya {kind: 'halaqoh'|'kelas',
  id, name, missingCount}.

  pengumuman) -- baris demi baris per halaqoh/kelas yang bolong,
  masing-masing punya tombol "Bereskan".
- AUDIT_KIND_CONFIG (baris 1411-1424) memetakan kind -> label entitas,
  keyword scope jabatan (buat cocokkan scope aktif), redirectPath, dan
  query param.
- Klik "Bereskan" -> cari scope role yang cocok (lewat
  PSAccess.getRoleScopeOptions/setRoleScope) berdasar scopeKeywords,
  set scope itu jadi aktif, lalu redirect ke
  redirectPath + '?' + queryParam + '=' + item.id
  (mis. /pages/halaqohAbsensi/?openHalaqoh=<id>).
- Tutup manual lewat tombol "x" (#_auditCloseBtn) cuma popup.remove()
  polos -- TIDAK ada request markSeen apa pun (karena memang tidak ada
  state itu). Jadi kalau reload halaman dan absensinya masih bolong,
  popup akan muncul lagi.
- Pakai tema warna ANNOUNCEMENT_THEMES.merah (dishare dari sistem
  pengumuman di atas, bukan definisi warna sendiri).

Backend handler (backend/server.js):
- 'absensi.owed' -> baris 2113 dan 13089
  (di sinilah logic "berapa hari dianggap belum diisi sejak awal
  tahun ajaran" dihitung -- kalau mau ubah threshold/definisi
  "bolong", edit di sini, bukan di frontend.)


3) HALAMAN "KELOLA AUDIT" -- switch ON/OFF per jenis (2026-07-28)
--------------------------------------------------------------------
Ditambahkan supaya Admin/Super Admin/Mudir bisa mematikan/menghidupkan
popup audit TANPA ubah kode, dari 1 halaman baru:
frontend/pages/kelolaAudit/index.html (nav: Pengaturan > "* Kelola Audit").

Beda dari pengumuman: audit TIDAK punya konsep "item/record" (dia
derived dari data live absensi), jadi bukan CRUD -- cuma 2 switch
ON/OFF, satu untuk 'halaqoh' satu untuk 'kelas', disimpan sebagai 1
baris state global (bukan per-akun, bukan per-halaqoh/kelas
individual). Pola yang dicontek: system.maintenance.get/set (file
JSON di backend/data/, BUKAN sheet/tabel), bukan pola pengumuman.

Backend (backend/server.js):
- State: `auditSettingsState = { halaqohActive, kelasActive, setBy,
  setAt }`, persist ke file backend/data/auditSettings.json
  (var AUDIT_SETTINGS_PATH, didefinisikan persis di sebelah
  MAINTENANCE_PATH di baris atas file).
- Action baru: 'audit.settings.get' (baca state) & 'audit.settings.set'
  (ubah, terima {halaqoh_active, kelas_active} boolean, salah satu
  boleh diisi sendiri-sendiri -- tidak harus dua-duanya).
- Otorisasi (di authorizeAction_): sama seperti pengumuman.list/save
  -- isAdmin || isSuperAdmin || isMudir. BUKAN superadmin-only.
- handleAbsensiOwed_ di-skip per config kalau kind-nya lagi
  dinonaktifkan (if (config.kind === 'halaqoh' && !auditSettingsState.
  halaqohActive) return; sama utk 'kelas') -- jadi kalau audit
  dimatikan, items dari kind itu otomatis tidak pernah dihasilkan.
  showAuditPopup di shared-shell.js TIDAK PERLU DIUBAH SAMA SEKALI --
  dia cuma nampilin apa pun yang dikirim server, jadi kalau server
  kirim array kosong, popup ya tidak muncul. Titik integrasi ada di
  BACKEND, bukan frontend.
- Ikut di-backup/di-restore: auditSettings.json disertakan di
  createBackup_() dan restoreFromBackupZip_() persis seperti
  maintenance.json (cari 'AUDIT_SETTINGS_PATH' kalau perlu ubah lagi).

Frontend (frontend/pages/kelolaAudit/index.html):
- Halaman baru, styling dicontek dari pages/pengumuman/index.html
  (variabel warna --paper/--ink/--muted, font Playfair+Poppins) tapi
  isinya cuma 2 kartu status (bukan list panjang + dialog form).
- canManage() sama persis dgn pengumuman: isAdmin||isSuperAdmin||
  isMudir. Kalau bukan salah satu itu, tombol toggle disembunyikan
  (walau halaman ini memang cuma bisa diakses role itu saja lewat
  shared-access.js redirectIfForbidden).
- Akses diatur di frontend/shared-access.js key 'kelolaAudit.html'
  (persis di sebelah 'pengumuman.html', rule sama).
- Entry nav ditambahkan di frontend/shared-nav.js, section
  'Pengaturan', persis di bawah entry "* Kelola Pengumuman".

BELUM/PERLU DIINGAT:

4) KIND KE-3: AUDIT HAFALAN HARIAN (2026-07-28)
--------------------------------------------------
Ditambahkan sebagai kind ketiga ('hafalan') di sistem audit yang sama
(bukan sistem terpisah) -- ikut nimbrung di 1 kartu popup
(_auditPopup), dan dapat switch ON/OFF ke-3 di halaman Kelola Audit
("Audit Hafalan Harian").

BEDA PENTING dari kind 'halaqoh'/'kelas': absensiHalaqoh/absensiKelas
itu 1 BARIS per (entitas, tanggal, sesi) yg isi kolom data_absensi
utk SEMUA santri sekaligus -- jadi cukup cek "ada barisnya atau
tidak". hafalanHarian itu 1 BARIS PER SANTRI PER TANGGAL (ada kolom
id_santri di tiap baris) -- jadi "sudah terisi" TIDAK BISA cuma cek
"ada baris" (itu pola halaqoh/kelas), harus cek SEMUA santri di
ROSTER halaqoh (kolom id_santri di baris halaqoh, lihat
editHalaqoh/dataKelompok) sudah masing-masing py minimal 1 baris
hafalanHarian hari itu. Ini keputusan sadar (sudah ditanya & dijawab
user 2026-07-28): PER-SANTRI, bukan per-halaqoh kayak absensi.
Konsekuensinya: kalau 1 santri dari 15 di halaqoh itu belum diisi
hafalannya hari itu, SELURUH halaqoh dianggap "gap" hari itu (bukan
cuma santri itu doang) -- karena unit yang di-audit tetap "halaqoh",
sama seperti kind lain, cuma kriteria "lengkap"-nya lebih ketat.

Definisi "terisi": HANYA cek ada barisnya atau tidak per (santri,
tanggal) -- TIDAK peduli kolom ziyadah/muroja_sabaqi/muroja_manzili
mana yang kosong (keputusan user: cukup 1 baris apa pun sudah
dianggap "sudah setor" hari itu, walau cuma isi salah satu kolom).

Backend (backend/server.js):
- Fungsi baru `collectHafalanGapItems_(activeTaId, taStartDate,
  yesterday, pengurusId)` -- terpisah dari collectAbsensiGapItems_
  (bukan lewat ABSENSI_OWED_CONFIGS) karena logikanya beda (per-santri
  vs per-baris). Baca sheet 'halaqoh' (filter pengampu = pengurusId,

  'mine' di collectAbsensiGapItems_ config 'halaqoh'), lalu utk tiap
  halaqoh: roster = parseIdList_(row.id_santri); kalau roster kosong,

  created_at halaqoh) s/d kemarin, tiap hari cek apakah SEMUA id di
  roster sudah py entri hafalanHarian hari itu (dihitung dari Set
  per (halaqoh, tanggal) hasil scan 1x seluruh sheet hafalanHarian).
- Dipanggil dari handleAbsensiOwed_ (action 'absensi.owed' -- nama
  action-nya TIDAK diubah walau sekarang juga mencakup hafalan,
  supaya tidak perlu ubah semua caller lama), di-guard oleh
  `auditSettingsState.hafalanActive`.
- auditSettingsState nambah field `hafalanActive` (default true),
  action 'audit.settings.set' terima payload tambahan
  `hafalan_active`. TIDAK perlu entry baru di authorizeAction_ --
  masih pakai action 'audit.settings.get'/'audit.settings.set' yang

5) FIX (2026-07-28): tombol "Bereskan" kadang menghapus scope alih-alih

------------------------------------------------------------------------

SEMPAT SALAH DIAGNOSIS (jangan diulang): percobaan pertama mengira
akar masalahnya ada di perbandingan "nama jabatan mentah" vs
`session.permissions.label` (label HASIL PRIORITAS gabungan semua

> isHalaqohCoordinator > isPengampuHalaqoh > isPengujiHafalan >

PERNAH muncul di rantai ini, jadi permissions.label seorang Mudir'Amm

"Mudir 'Amm"). Sempat dicoba fix dengan MENGHAPUS TOTAL logic ganti-
scope dari tombol Bereskan -- tapi ternyata itu skalah: ganti-scope
ini memang FITUR YANG DIINGINKAN (biar sidebar/menu ikut berubah
sesuai peran yg lagi dibereskan), bukan sesuatu yang harus dibuang.
Simulasi ulang pakai data jabatan asli (lewat node, load langsung

AKAR MASALAH SEBENARNYA (ditemukan lewat simulasi node meniru

sungguhan -- DB lokal isinya 80 pengurus asli jadi sengaja tidak

    var activeLabel = getActiveRoleScopeLabel(session) || permissions.label || '';
    if (normalizeAccessText(selected.label) === normalizeAccessText(activeLabel)) {
      // Switch ke scope yang sama dengan yang aktif = kembali ke default

Ini FITUR yang disengaja utk dropdown MANUAL di header (klik opsi yg

HAL YANG SERING BIKIN BINGUNG SAAT EDIT
------------------------------------------
- Dua fungsi sync- ini API SHAPE-nya mirip (fetch -> cek json.ok ->
  cek items.length) tapi RENDER-nya beda pola: pengumuman = antrean
  1-per-1 (_announcementQueue + showNextAnnouncement recursive),
  audit = 1 kartu isi semua item sekaligus (showAuditPopup dipanggil

- Posisi CSS sengaja dibedakan (kanan-bawah vs kiri-bawah) supaya
