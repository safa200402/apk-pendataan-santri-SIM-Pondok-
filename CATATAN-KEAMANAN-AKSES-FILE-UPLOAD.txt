1. MASALAH
----------
backend/server.js:29590 memasang:
  app.use(express.static(FRONTEND_DIR, { ... }))

FRONTEND_DIR mencakup SELURUH folder frontend/, termasuk 15 folder upload
di BACKUP_FILE_DIRS_ (backend/server.js:656-673): portal-logos,
profile-photos, kelas-docs, santri-docs, izin-pulang-fotos,
santri-sakit-fotos, pelanggaran-fotos, absensi-pengurus-fotos,
buku-digital, bank-soal, jam-digital-logo, jam-digital-audio,
jam-digital-videos, pengumuman-media, catatan-media, quiz-media.

express.static TIDAK lewat middleware auth apa pun -> siapa saja yang
tahu/nebak URL file (dari response API, history browser, forward chat)
bisa akses langsung, termasuk dokumen KK/akte santri, foto pelanggaran,
foto sakit, foto izin pulang -- walau tidak pernah login / sudah logout.
Nama file dikasih random suffix (saveSantriDoc_ ~16550-16567, pola
`fieldKey-santriId-timestamp-<4byte hex>.ext`) tapi itu cuma
security-by-obscurity, bukan access control.

Constraint: auth app ini BUKAN cookie session, tapi custom token di
header `token` per request API (authenticateRequest_, server.js:20030).
<img src>/<a href>/window.open() dari browser tidak bisa nyisipkan
header custom -> route file baru tidak bisa cuma andalkan header token
biasa.

6. ACCEPTANCE CRITERIA (SALIN DARI PERMINTAAN AWAL, JANGAN DIUBAH)
---------------------------------------------------------------------
- Request langsung ke URL file privat TANPA login -> ditolak (401/403).
- Login tapi TIDAK punya akses ke entitas terkait -> ditolak, bukan
  cuma cek "sudah login".
- Login DAN berwenang -> tetap bisa lihat/download seperti biasa.
- Tidak ada regresi di backup, restore, madingPublik, jamDigitalRemote.
- Path traversal di parameter filename -> ditolak.
